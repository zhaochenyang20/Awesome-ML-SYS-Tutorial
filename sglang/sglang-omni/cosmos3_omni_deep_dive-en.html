Internal Reading Material · Cosmos 3 Omni Mechanism & Architecture

One Set of Weights, Two Kinds of Decoding

MoT's modality decoupling, AR + diffusion joint attention, and what it means for the Omni serving abstraction

Cosmos 3 uses Mixture-of-Transformers to pack two decoding modes with completely different runtime characteristics — the autoregressive decode of text and the diffusion denoising of the other modalities — into the same set of weights, the same sequence, and the same single attention. This material breaks it down from the low-level mechanism all the way up to the serving abstraction: first making clear what the "mixture" actually mixes, then giving the math of the three kinds of attention, the complete decode process with pseudocode, the nature of the latent, and finally landing on the abstraction orientation of our SGLang Omni.

01 — Architecture Overview

MoT Dual-Tower: 5 Modality-Separated Weight Sets, Sharing One Attention

Cosmos 3 is a Mixture-of-Transformers. It is not a "universal brain," but rather separates each modality's weights and then stitches them together with one shared attention. Text goes through the autoregressive tower; image / video / audio / action go through the diffusion tower.

02 — Concept Clarification

What Exactly Is Being "Mixed"

The most common misconception: thinking there's some parameter that sometimes denoises and sometimes decodes. There is no such parameter. MoT's "mixture" refers to a single transformer that simultaneously holds several modality-separated weight sets; one mixed sequence flows through, and each token is routed by modality to its own set.

The MoT paper puts it very cleanly: it decouples all non-embedding parameters by modality — feed-forward, attention projection matrices, layer normalization — one set per modality, with only self-attention shared across the full sequence as a single operation. So text weights only ever process text tokens, image weights only ever process image latents, and they never switch posts.

Why "Not Sharing Parameters" and "The Same Attention" Aren't Contradictory

The key point in one sentence: the "mixing" operation of attention itself has no learnable parameters. The parameters are all in the projections on both sides (Q/K/V/O) and the FFN, and those are one set per modality. The softmax(QK⊤)V in the middle that stitches them together is parameter-free — it merely mixes together the q/k/v that each side has already computed. Unfolding a single layer:

Sparse Activation: Not Every Forward Uses All Parameters

Because parameters are decoupled by modality, what a single forward truly activates is only "the weight sets of the few modalities that appear in this sequence"; it doesn't touch the FFN / projections of any other modality. This is why MoT is called "sparse" (in the paper, speech uses only about 37% of the FLOPs of the dense baseline, and about 56% in the Chameleon setting). Two things need to be distinguished:

DimensionSparse?Meaning
Active parameters per forward (FLOPs)SparseOnly computes the sets of modalities that appear; "all are used" is wrong
Parameters that must reside in VRAM (loading)Not necessarilyA general any-to-any service doesn't know in advance what modalities the next request carries, so it often still needs them all resident; saving VRAM relies on single-purpose deployment loading only the slice it needs (this is exactly the point of the separate Cosmos3ReasonerForConditionalGeneration arch class)
03 — Comparison

The Difference from Ming-Omni: Joint Attention vs Baton-Passing

Intuitively, Cosmos and Ming-Omni look very similar — both are "one AR part + one diffusion part, with separate parameters." At that level it's right. The difference lies in the tightness of the coupling.

Ming-OmniCosmos MoT
Structurededicated encoders → Ling (MoE) understands + emits text → passes the baton to a separate audio decoder / diffusion modeljust one stack of layers; text tokens and latents are in the same sequence from start to finish
Attentiontwo sets: one for the backbone, one for the diffusion, each independentone shared attention per layer, cross-modality mutual visibility
How the condition enters generationthe backbone produces conditioning, fed to the downstream network all at oncelatents read the condition within the same attention at every layer (deep, bidirectional, layer-by-layer)
Can it be cleanly split into two stagesyes (thinker → diffusion, relay carries the hidden state)hard — there's no "baton-passing point," the whole generation is one fused forward

The analogy, used just once: Ming is two meetings — meeting A writes the minutes, meeting B opens by reading them aloud; MoT is everyone sitting at the same table, conversing in real time at every layer — each speaking their own language (their own weights), but in the same conversation (the same attention). This difference has direct consequences for how we carve Stages; see Section 10.

04 — Math

The Math of Three Kinds of Attention

The difference among the three is almost entirely in the mask and how many projection sets are used; the core formula is the same softmax. Notation: the hidden state hp at position p, projected into q/k/v, head dimension d.

① Traditional Autoregressive (Causal Mask)

One weight set, shared by all tokens:

qi = WQ hi ， ki = WK hi ， vi = WV hi
αij = softmaxj( qi · kj / √d ) ， only j ≤ i (causal / lower-triangular)
oi = Σj≤i αij vj

Each token sees only itself and the past. Generation is serial token-by-token, and past k/v go into the KV-cache. Objective: next-token cross-entropy.

② Traditional Diffusion (DiT, Fully-Connected)

latent tokens z1..m = the representation of the whole (noisy) image/video at noise level t, with t injected via AdaLN or embedding. One weight set:

qi = WQ zi ， …(zi depends on noise level t)
αij = softmaxj( qi · kj / √d ) ， all j (fully-connected / bidirectional)
oi = Σj αij vj , the network predicts εθ(zt, t, c), running T steps

Each patch sees all patches, with no causal structure. One forward = one denoise step; z changes entirely between steps, so there is no KV-cache.

③ Cosmos (MoT + Transfusion-Style Joint)

One sequence mixes text tokens and latents, with the modality m(p) of position p. Projections are separated by modality; the mask is a block-causal mix:

qp = WQm(p) hp ， kp = WKm(p) hp ， vp = WVm(p) hp
αpq = softmaxq( qp · kq / √d + Mpq ) ， op = Σq αpq vq
Mpq = 0 (visible) / −∞ (invisible)
text p: causal (q in an earlier block, or q ≤ p)　　image p∈block B: {everything before B} ∪ {everything inside B, bidirectional}

Key: no matter which set of W, qp and kq both land in the same ℝd, so the cross-modality qp·kq is a well-defined real number — this is the mathematical entry point for text and image "being able to converse." The three masks drawn as matrices:

Walking Through at the Index Level

Minimal sequence [t1, t2, i1, i2, i3], positions 1 and 2 are text, 3, 4, 5 are one image block. Take the image query i2 (pos 4); it can see {1,2,3,4,5}:

s4,1 = q4·k1 / √d (q4=WQimgh4, k1=WKtxth1) ← image query · text key
s4,2 = q4·k2 / √d ← image query · text key
s4,3, s4,4, s4,5 ← image · image (intra-block bidirectional, including the "later" i3)
α4,· = softmax( {s4,1 … s4,5} )
o4 = α4,1v1 + α4,2v2 + α4,3v3 + α4,4v4 + α4,5v5

o4 is a convex combination spanning text values (purple, WVtxt) and image values (teal, WVimg). The text condition enters the image patch right within this one weighted sum — no second network, no baton-passing, just the same softmax's denominator containing both text keys and image keys. The mask decides which q this row sums over, the modality decides which set of W computes each position's q/k/v, and both are stuffed into the same softmax(QK⊤/√d + M)V.

05 — KV-cache

Why Diffusion Latents Can't Be KV-cached

The KV-cache is an optimization for "incremental sequence extension." For it to hold, two conditions must be met at once: the context is append-only (appended only at the tail), and the hidden states of existing positions are frozen (k/v fixed and reusable). The diffusion loop breaks both.

PremiseAR decodediffusion denoise
Is it append-onlyYes, appended token-by-token at the tailNo, the token count is always m, there are no "new positions"
Are existing positions' hidden states frozenYes, x1..t never change again → k/v fixedNo, denoising is by definition z(s−1) ≠ z(s), h changes entirely each step → k/v differs each step
z(T) → z(T−1) → … → z(0) (fixed length of m latents, repeatedly refined, not extended)
kj(s−1) = WK hj(s−1) ≠ WK hj(s) = kj(s) ← the k/v cached from the previous step are wrong this step, must all be recomputed
Two boundaries (don't memorize rigidly): ① The fixed condition (text prompt) does not change across the T steps, so its k/v can be computed once and reused for T steps — strictly speaking, what cannot be cached is only the latents currently being denoised. ② The DeepCache family of reusing features across adjacent steps is an approximation (features change slowly between adjacent steps), not exact KV reuse — don't conflate them.
06 — The Full Decoding Process

The Complete Decode Process

At the bottom there are only two decoding primitives; a request of any modality combination is a sequence orchestrated from these two by control tokens.

primitive · AR step

Append 1 discrete token at the tail, causal attention, k/v immediately enters the cache and is reused permanently. Text goes through this, growing token-by-token.

primitive · denoise block

Append a fixed m of continuous latents at the tail, intra-block bidirectional + attend to the prefix, iteratively denoise in place for T steps, and when done the whole block's k/v enters the cache. image / video / audio / action go through this, with the block length fixed.

Phase Model: Strictly Append-Only, Only One Region Active at a Time

The whole sequence grows block by block from left to right. At any moment only one region is "active"; everything to its left is frozen, and nothing to its right exists yet. A text span and a latent block are never active simultaneously — this is why the contradictory scenario of "text growing from the middle while a latent moves at the same time" simply does not exist.

Main Loop

prefix_kv = [ {"K": empty[0,d], "V": empty[0,d]} for _ in range(L) ]  # one per layer
H = 0; h_new = embed(BOS)
while not done:
    # ===== AR text phase =====
    while True:
        x = decode_one_text_token(h_new, pos=H, prefix_kv); H += 1
        if x == <EOS>: done = True; break
        if x == <BOI>: break        # begin-image/audio/video/action
        h_new = embed(x)
    if done: break

    # ===== denoise phase (block size m fixed at this moment) =====
    m = resolve_block_size(spec)              # image=#patches; video=frames×patch; audio=framerate×duration; action=#steps×D
    block_positions = range(H, H+m)           # position ids determined immediately, unchanged during denoise
    z = noise(m)                              # z^(T)
    for s in range(T, 0, -1):
        eps = forward_denoise(z, s, block_positions, prefix_kv)  # only forward these m
        z   = sampler_update(z, eps, s)                          # z^(s)→z^(s-1), z modified outside the network
    finalize_block_into_cache(z, block_positions, prefix_kv); H += m  # clean K/V enters cache
    h_new = embed(<EOI>)

Two Inner Loops: AR Single-Step and Denoise Single-Step (the difference is all here)

# —— AR: add only 1 position, concat prefix KV, append after compute (append-only) ——
def decode_one_text_token(h_new, pos, prefix_kv):
    for l in range(L):
        h = layernorm_txt[l](h_new)
        q,k,v = W_Q_txt[l]@h, W_K_txt[l]@h, W_V_txt[l]@h      # text projection
        q,k = rope(q,pos), rope(k,pos)
        K = concat(prefix_kv[l]["K"], k); V = concat(prefix_kv[l]["V"], v)   # [H+1, d]
        a = softmax(q@K.T / sqrt(d)); o = a@V                 # causal: the new token sees all H+1, no explicit mask needed
        h_new = h_new + W_O_txt[l]@o; h_new = h_new + FFN_txt[l](h_new)
        prefix_kv[l]["K"], prefix_kv[l]["V"] = K, V           # append, never changed again
    return sample(unembed(h_new))

# —— denoise: only forward these m latents, read prefix KV but don't write; intra-block bidirectional ——
def forward_denoise(z, s, block_positions, prefix_kv):
    h = latent_in_proj(z) + timestep_embed(s)                 # [m, D], noise level injected
    for l in range(L):
        hn = layernorm_img[l](h)
        q,k,v = hn@W_Q_img[l].T, hn@W_K_img[l].T, hn@W_V_img[l].T   # [m,d] recomputed each step (z changed)
        q,k = rope(q,block_positions), rope(k,block_positions)      # position = constant
        Kp,Vp = prefix_kv[l]["K"], prefix_kv[l]["V"]          # [H,d] frozen, read cache no recompute
        K = concat(Kp,k); V = concat(Vp,v)                    # [H+m, d]
        a = softmax(q@K.T / sqrt(d))                          # [m, H+m], no lower-triangular inside block = bidirectional
        h = h + (a@V)@W_O_img[l].T; h = h + FFN_img[l](h)
        # note: never write prefix_kv[l] here, no cache during denoise
    return eps_head(h)                                        # [m, D_latent] predict noise/velocity

The Third Inner Loop: Block Finalize (denoise done → clean K/V enters cache)

# —— after denoise, z is z^(0) (clean); append the whole block using the clean K/V, after which this block becomes a frozen prefix ——
def finalize_block_into_cache(z0, block_positions, prefix_kv):
    h0 = latent_in_proj(z0)                               # clean latent, no longer add the noise-level embedding
    for l in range(L):
        hn = layernorm_img[l](h0)
        k  = rope(hn@W_K_img[l].T, block_positions)        # position = the same batch of constants
        v  =      hn@W_V_img[l].T
        prefix_kv[l]["K"] = concat(prefix_kv[l]["K"], k)   # H → H+m
        prefix_kv[l]["V"] = concat(prefix_kv[l]["V"], v)   # frozen thereafter, reusable by later text

Note that what enters the cache is the clean z(0), not some intermediate denoise step: the semantics that later text tokens attend to must be "the picture already drawn." With this the trio is complete — the main loop orchestrates decode_one_text_token (AR step), forward_denoise (denoise block single-step), and finalize_block_into_cache (commit to cache); any modality request is a permutation of these three.

The only source of the latent changing each step is the sampler, not the text: sampler_update is a closed-form update outside the network (DDIM/flow-matching) that advances the current noisy z and predicted eps by one notch to z(s−1). z changed → in the next forward_denoise, h and q/k/v all change → so their KV cannot be reused across steps; whereas the prefix has never entered this update, stays perfectly still, and so can be reused.

Per-Region KV Behavior

RegionLengthIts own K/V while generating itPrefix K/V meanwhileAfter finalize
text spangrows token-by-tokencomputed once then cached, reusedreusedfrozen into cache
latent blockfixed mfully recomputed each denoise stepreused (the prefix is frozen)the whole block enters cache using clean z's K/V

So within a single generation the KV is a third form — "prefix cached, denoise block recomputed each step" — neither pure AR's fully-cached, nor pure DiT's not-cached-at-all. This is a class the scheduler must handle separately. (Detail: what enters the cache is the K/V of the clean z(0), because later text attends to "the picture already drawn.")

07 — Paths

Reasoner vs Generator

The "AR + denoise alternation" hybrid decoding above is unique to the Generator; the Reasoner is its degenerate case — the sequence has no denoise block at all, only pure AR left. The criterion is the output modality, not the input.

ReasonerGenerator
Triggeroutput = pure textoutput contains image/video/audio/action
Denoise blocks in the sequencenoneyes (one or more)
Phasesone AR phase throughoutAR text phase ↔ denoise phase, alternating
Weights usedtext weights + input-side encodingthe above + target-modality diffusion weights
KV behaviortoken-by-token incremental cache throughouttext spans incrementally cached; denoise blocks recompute themselves each step, reuse the prefix, and commit the whole block to cache when done
Can it be deployed separatelyyes (the arch class loads only the understanding side)needs the diffusion weight set

The input modality only determines what condition tokens go into the prefix; the output modality determines which path is taken and whether there is a denoise phase. This is also the root of that CI blind spot: the same input combination (e.g. image+text) with different outputs (text vs video) → the code paths do not overlap at all. The first dimension of the coverage matrix must be the (input set, output modality) pair.

08 — Examples

Per-Modality Request Examples

Notation: [...] is a span of tokens and its weights/role; ⟨denoise m⟩ means append m latents at the tail and denoise in place for T steps, entering the cache when done.

text → audio + text (e.g. "read this sentence aloud and give a transcript"): stuff the text condition into the prefix → AR emits the transcript up to <BOA> → ⟨denoise ma audio latents, attending to the prefix text that contains the just-written transcript — this is the source of "what is spoken matches what is written"⟩ → optionally continue text → <EOS>.

img+text → action: prefix with image encoding + text instruction → directly ⟨denoise mact action latents; mact = #steps × embodiment dimension D (single-arm Franka 10D, Agibot 29D…)⟩. No AR text span.

image → video (i2v): prefix with the first-frame encoding → ⟨denoise mv video latents, spatiotemporal bidirectional + attend to the first frame⟩. The forward-dynamics rollout is its chunked-autoregressive version: [first frame][action_chunk_0]⟨denoise chunk0⟩ → take the last frame of the generated video as the first frame of the next block → then another block.

09 — latent

The Nature of Latents, and How They Attend Together with Text

A latent is not "a unified embedding across modalities." Quite the opposite: each modality's latent is an independent vector, not interchangeable with the others. What lets them attend in the same arena as text is not a unified representation, but being mapped by their respective projections into the same d-dimensional scoring space.

A Latent Is a Modality-Local Continuous Tensor

A latent is squeezed out by that modality's own encoder: image latent = a VAE compressing the image into an [h×w, c] patch grid; video latent = a spatiotemporal VAE's [frames′×h′×w′, c]; audio latent = an audio VAE's [frames, c]; action latent = a trajectory's [T, D]. There is no shared semantics among them, and even the dimension c may differ. Cosmos precisely does not stuff all modalities into one universal representation.

What Is Unified Is the Post-Projection d-Dimensional Space, Not the Latent

The text side is equally local (a table lookup yields [D_text]). What lets them "converse" is each modality's own input projection + Q/K/V projections, pulling the local representation to the same head dimension d:

text:　e = embed_table[tok] [D_txt] → h = in_proj_txt(e) [D] → q = WQtxt·LN(h) [d]
image: z = vae_encode(patch) [c_img] → h = in_proj_img(z) [D] → q = WQimg·LN(h) [d]
different starting points, different dimensions, but the two in_proj each pull to the same trunk width D, then each W pulls to the same d
→ qimg · ktxt / √d is the dot product of two same-dimensional real vectors = an ordinary scalar. Attention only does dot products on d-dimensional vectors and doesn't care about the origin.

The analogy in one line: different currencies, each converted to US dollars at its own exchange rate, can then be summed — latents are the national currencies (not interchangeable), in_proj + WQ/K/V are the respective exchange rates, the d-dimensional space is the US dollar, and attention only does arithmetic at the "dollar" layer. This is exactly where "MoT parameters separated by modality" lands: each modality needs its own access path.

latent → Modality Decoder: Reconstructing to the Signal Domain

What denoising produces is the target modality's latent, not a playable waveform / viewable pixels. Downstream there is still a modality-specific decoder that pulls the latent back to the signal domain: audio latent → vocoder/codec → waveform; video/image latent → VAE decoder → per-frame pixels. This is the same recipe as latent diffusion (denoise a low-dimensional latent, and the VAE/vocoder at the end pulls it back to high dimensions).

Two wordings to get exactly right: ① What the Cosmos diffusion path denoises is a continuous latent, not a discrete "audio token" (the latter is the AR codebook route of Qwen3 talker / Fish, a different mechanism). ② This decoder is usually a VAE/vocoder trained independently outside the trunk, not inside those L MoT layers and not participating in the joint attention — so it is naturally another (streamable) terminal stage on the pipeline, with relay carrying the latent in between.
10 — Abstraction

Abstraction Implications for SGLang Omni

The real layering is Coordinator → Stage → Scheduler → ModelRunner → forward; the relay (including the CommEngine) is an orthogonal transport beneath the Stage that moves tensors along the graph's edges — it is not above the ModelRunner. Unification happens at the Stage, a model-agnostic IO shell ("never checks the scheduler type"), and heterogeneity is pushed down to the Scheduler / ModelRunner.

Judgment 1

Unify at the Stage Shell, Not the Communication Layer

KV-cache / continuous batching are meaningless for diffusion, and CFG / the denoising scheduler are meaningless for AR. Forcibly unifying the Engine = building an if-modality branch body. The correct seam is the Stage (one code path that never checks the scheduler type), with heterogeneity pushed down to the Scheduler / ModelRunner. Cosmos's Reasoner / Generator land on disjoint weight subsets — exactly the basis for them to be different runners, each able to disaggregate and load only its own slice.

Judgment 2

The Denoise Block Is Different Instantiations of the Same Primitive

The decoding mechanism is the same for image/video/audio/action (intra-block bidirectional + denoise T steps); the only differences are three parameterizations: which diffusion weight set to use, how the block size m is computed, and the intra-block positional encoding (2D/3D/1D). So there's no need for one decode loop per modality — a single "denoise block" DiffusionModelRunner + per-modality injection (weights, m, positional encoding) suffices. This matches exactly the design in the docs where DiffusionModelRunner is meant to become a first-class runner.

Judgment 3

The "Third Form" of KV Needs a Separate Scheduler Track

Within a single generation request the KV is a hybrid of "prefix cached, denoise block recomputed each step, whole block committed to cache when done." It is neither pure AR's fully-cached nor pure DiT's not-cached-at-all. Memory reclamation, preemption, and VRAM budgeting all have to be designed around this form — not by applying an LLM's KV management.

Judgment 4

Joint Attention Resists the thinker→talker Two-Stage Split

Ming is loosely coupled, naturally two Stages (thinker → diffusion, relay carries the hidden state). If Cosmos is truly joint-attention, then every layer of the denoise block must read the text condition within the same attention — there is no baton-passing point — the whole generation is one fused forward, and is better treated as a single Stage running one runner that does both AR conditioning and denoising. This may be its biggest challenge to our existing producer-consumer carving. (Meanwhile the VAE/vocoder reconstruction stage at the end is still another stage that can be cleanly carved out.)

11 — Honest Boundaries

Honest Boundaries: What Is a Reading vs What Needs the White Paper to Nail Down

The "AR spans alternating with denoise blocks within a single sequence + block-causal mask + modality-decoupled projections" in Sections 02, 04, and 06 of this material is a MoT + Transfusion reading. The model card mentions MoT / single framework / AR tower / diffusion tower, all of which point to this reading (the MoT paper itself studies the setting of text AR + image diffusion within one transformer). But the card does not confirm the following points verbatim; they require the white paper / config / HF arch class implementation to be pinned down:

Open pointIf A (joint, this material's reading)If B (cross-attention baton-passing, more like Ming)
Relation between text K/V and latentsin the same softmax's denominator (joint)a separate cross-attention (baton-passing)
Can it be split in twohard, the whole generation is one fused forwardyes, backbone → diffusion, two stages

Also needing implementation confirmation: whether there is a shared trunk between the two towers, whether the input encoder tower is independent of the MoT backbone, how much the Reasoner arch class actually cuts, and which scheduler the diffusion hangs under in the Cosmos SGLang cookbook. These do not affect this material's description of the mechanism's principles, but they do affect the concrete carving onto our Stage / runner.
